# Level data as loaded JSON, not bundled TS objects

`Game.ts` had its platform layout and spawn point hardcoded, and we're introducing the first reusable "tool" of the framework: a `Level` describing spawn point, platform positions, world width, and the finish line. Two real options existed — a typed TS object literal (compile-time checked, but a rebuild is needed to add or edit a level) or a JSON file (no compile-time shape checking, but editable and addable without touching code). We chose **JSON, loaded through Phaser's Loader** (`this.load.json('level-1', 'assets/levels/level-1.json')` in `preload()`) specifically so future levels can be added or tweaked as data, not code changes — the whole point of calling this a "framework" is that adding a level shouldn't require touching `Game.ts`.

This does give up compile-time verification of a level file's shape; a `Level` TypeScript interface documents the expected fields for the code that reads the loaded JSON, but nothing checks a given JSON file against it before runtime. If malformed level files become a real problem, revisit with runtime validation — not by quietly moving back to bundled TS objects, which would defeat the reason this was chosen.
